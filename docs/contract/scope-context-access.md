# Scope Context access

`context.edit` is a canonical, exact-scope permission in Tower's existing actor/group permission grants. Current workspace membership and effective canonical group membership are checked on each request. It provides scope/context visibility and create, rename, reorder, reparent, link, unlink and confirmed subtree deletion. `scope.manage` remains an editing fallback and separately authorizes scope administration and grant changes. Neither permission implies channel or linked-target access, or access to a descendant scope.

Context `capabilities.edit` describes effective editing; legacy `capabilities.manage` is its compatibility alias. `capabilities.scope_manage` describes scope administration. Clients must never use context `manage` to authorize scope administration. Context reads, events and record recovery use the same scope visibility predicate. Grant/group changes use the established sync authorization epoch reset semantics.

GET `/api/v4/flightdeck-pg/workspaces/:workspaceId/scopes/:scopeId/grants` returns `revision`, `can_manage`, canonical principal bundles, management-only workspace principal choices and effective actor provenance. A visible reader sees only their own provenance; a scope manager sees all workspace actors and grants. Group provenance identifies the granting group, including access reached through existing nested group membership.

PUT the same route requires `scope.manage`, a scope edit lease acquired through `/edit-leases/acquire` with `entity_type: scope`, and the GET `expected_revision`. The principal must be a workspace actor or canonical group. `role: context_editor` adds `context.edit`; `role: scope_manager` adds `scope.manage`. Adds preserve every existing permission; selecting Context editor cannot silently remove Scope manager. To remove role authority, send `revoke: true`; it removes only these two role permissions and preserves custom grants such as `channel.create` and pre-existing `scope.read`. Re-grant the narrower role explicitly after revoke. A group-derived grant must be revoked at the group source. No actor identity or membership changes occur.

Roles are UI translations, never a second authority table. Revision conflicts and invalid/expired/foreign leases are 409. Updates, audit, outbox and lease consumption commit together under the existing scope transaction lock. Production grants are operator actions; tests use disposable PostgreSQL fixtures and labelled browser fixtures.
